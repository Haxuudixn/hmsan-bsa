# HMSAN-BSA Model and Algorithm Design

## 1. Purpose

This project builds a trainable model and engineering skeleton for classifying tender document slices and detecting section boundaries. The selected model direction is a deep HMSAN-style architecture enhanced with boundary-aware section modeling:

**HMSAN-BSA: Hierarchical Memory Sparse Attention Network with Boundary-aware Section Aggregation**

The system should support current Excel-based block annotations and future supplemental PDF annotation files. The first engineering version must run end-to-end on the existing `all_blocks.xlsx` data, while keeping the model interfaces ready for full multimodal training once more labeled PDFs are added.

## 4. Label System

The model uses three related label groups.

### 4.1 Block Classification Label

`y_cls` is the main supervised label. It maps the Excel `label` column into class IDs.

Rules:

- Non-empty labels are supervised.
- Empty labels are set to `ignore_index`.
- Multi-label pages remain valid at block level. The block keeps its own label.
- Class mapping is stored in `configs/labels.yaml`.

### 4.2 Boundary Label

`y_boundary` is derived from ordered block and page labels:

- `B-SECTION`: first labeled block/page of a new section
- `I-SECTION`: continuation of the current section
- `E-SECTION`: final block/page of the current section where detectable
- `O`: unlabeled, unknown, or invalid region

For the current Excel data, boundary labels can be generated by grouping labeled pages into continuous spans. Example spans observed in the current labeled PDF:

### 4.3 Section Label

`y_section` represents the page-span or chapter-level label. It is used by the section memory and section prediction head.

Rules:

- For single-label pages, section label equals the page's dominant block label.
- For multi-label pages, keep block labels and assign a section label using a deterministic strategy:
  - If one label continues from adjacent pages, use the continuing label as the main section label.
  - Store the remaining label as an auxiliary page/block label.
  - If no continuation exists, mark the page as mixed and train only block-level loss for that page.

## 5. Model Architecture

HMSAN-BSA contains six modules.

### 5.1 Block Multi-modal Encoder

Input: one block with text, optional image, bbox, font, and style features.

Text branch:

- Full mode: Chinese pretrained encoder such as RoBERTa-wwm-ext.
- Lite mode: token embedding plus small Transformer or BiLSTM.

Image branch:

- Full mode: ResNet-50 or ViT over rendered block image.
- Lite mode: zero vector or handcrafted image metadata stand-in until block screenshots are available.

Layout/style branch:

- MLP over normalized bbox and style features:
  - `x0, y0, x1, y1, w, h, cx, cy`
  - normalized font size
  - bold flag
  - block type embedding
  - font family embedding when available

Fusion sequence:

```text
[CLS_block] text_tokens image_tokens layout_token font_token
```

Output:

- `h_block`: base block embedding
- optional token-level states for future fine-grained analysis

### 5.2 Intra-page Sparse Fusion

Input: all block embeddings from one page.

Page sequence:

```text
[CLS_page] block_1 block_2 ... block_k [MEM_page_out]
```

Because page-level block counts are small, standard Transformer attention is sufficient at this layer. Sparse attention is reserved for long token sequences inside the block encoder.

Output:

- `h_block_ctx`: context-enhanced block embeddings
- `h_page`: page representation from `[CLS_page]`
- `m_page`: page memory from `[MEM_page_out]`

### 5.3 Boundary-aware Section Detector

Input:

- `h_block_ctx`
- page position features
- layout/style features
- local neighboring block/page features

Output:

- `boundary_logits` over `B-SECTION`, `I-SECTION`, `E-SECTION`, `O`

The boundary detector is a neural auxiliary head. Rules based on title keywords, directory structure, font changes, and page-position jumps are used as derived features or weak labels, not as the final classifier.

### 5.4 Inter-page Memory Propagation

The model processes pages in order and passes memory across pages:

```text
m_page_t = PageEncoder(page_t, m_page_{t-1}, m_section_{t-1})
```

Memory types:

- `m_page`: short-term cross-page context
- `m_section`: long-term current-section context

These memory tokens are prepended to the page sequence and participate in attention.

### 5.5 Section Memory Update

The section memory is updated according to boundary evidence:

```text
if boundary == B-SECTION:
    m_section = init_from(current_page)
elif boundary == I-SECTION:
    m_section = gated_update(m_section, current_page)
elif boundary == E-SECTION:
    m_section = finalize_or_decay(m_section)
else:
    m_section = keep_or_decay(m_section)
```

The recommended implementation is a GRU-style or attention-gated update:

```text
z = sigmoid(Wz * [m_section_prev, h_page])
r = sigmoid(Wr * [m_section_prev, h_page])
m_candidate = tanh(Wm * [r * m_section_prev, h_page])
m_section = (1 - z) * m_section_prev + z * m_candidate
```

This gives the architecture an interpretable way to model whether a tender document page continues the previous section.

### 5.6 Joint Prediction Heads

The model predicts:

- `block_label_logits`
- `boundary_logits`
- `section_label_logits`

Total loss:

```text
L = L_cls + alpha * L_boundary + beta * L_section + gamma * L_crf
```

Where:

- `L_cls`: block classification cross entropy with ignore index
- `L_boundary`: boundary classification loss
- `L_section`: section-level classification loss
- `L_crf`: optional sequence transition loss for valid label ordering

The CRF/Viterbi layer is optional in the first engineering version but should be represented in the interface.

## 6. Inference Algorithm

Inference is streamable by page:

1. Load and normalize document blocks.
2. Initialize `m_page_0` and `m_section_0`.
3. For each page in page order:
   - encode blocks
   - perform page fusion
   - predict block labels and boundary labels
   - update page memory
   - update section memory
4. Apply sequence smoothing with Viterbi or CRF when enabled.
5. Export predictions at block level and page/section span level.

This supports arbitrary-length tender documents without loading the full document into a single Transformer window.

## 8. Training Strategy

### Stage 1: Data Validation

Goals:

- Parse Excel into Document/Page/Block hierarchy.
- Normalize bbox and style features.
- Encode labels.
- Generate boundary labels.
- Produce label distribution reports.

Success criteria:

- Dataset loads without dropping valid labeled blocks.
- Empty labels are ignored, not converted to a real class.
- Boundary spans match observed section transitions.

### Stage 2: Block Encoder Training

Train:

```text
BlockEncoder + BlockClassificationHead
```

Purpose:

- Establish a single-block baseline.
- Validate that text/layout/style features carry signal.

### Stage 3: Page Fusion Training

Train:

```text
BlockEncoder + PageEncoder + BlockClassificationHead
```

Purpose:

- Let image or sparse text blocks inherit context from neighboring text blocks.
- Improve page-level semantic coherence.

### Stage 4: Memory and Boundary Joint Training

Train:

```text
BlockEncoder
+ PageEncoder
+ PageMemory
+ SectionMemory
+ BoundaryHead
+ SectionHead
+ ClassificationHead
```

Training windows:

- Use sliding page windows, such as 5 to 10 pages.
- Preserve page order.
- Carry or reinitialize memory according to configuration.

Purpose:

- Learn cross-page continuity.
- Learn section starts and continuations.
- Reduce unreasonable label jumps.

## 9. Evaluation Plan

### Block-level Metrics

- Accuracy
- Macro-F1
- Weighted-F1
- per-class precision/recall/F1

### Boundary Metrics

- Boundary precision
- Boundary recall
- Boundary F1
- section-start detection accuracy

### Section-span Metrics

- Segment accuracy
- Section IoU
- predicted span vs. true span overlap
- over-segmentation and under-segmentation counts

### Current Data Caveat

With the current labeled data, final model accuracy should not be treated as meaningful generalization evidence. The first version should claim:

- data pipeline works
- boundary labels can be generated
- model forward pass works
- losses are computable
- metrics are reportable

After additional labeled PDFs are supplied, the same framework can be trained and evaluated with real train/validation/test splits.

## 10. Initial Implementation Scope

The first implementation plan should build:

1. Excel loader and schema normalization.
2. Label schema and boundary label builder.
3. PyTorch Dataset and collate function for document/page/block batches.
4. Lite HMSAN-BSA model with the same interfaces as full mode.
5. Multi-task loss computation.
6. Training script that can overfit the current small labeled subset.
7. Evaluation script with block, boundary, and section metrics.
8. Prediction/export script for Excel output.
9. Unit tests for boundary construction, dataset batching, and model forward pass.

Full pretrained encoders, block screenshots, OCR enrichment, and CRF decoding should be implemented after the skeleton is proven on current annotations or when additional labeled PDFs are available.

## 11. Open Assumptions

- Future PDF annotations will preserve or can be converted into the same Document/Page/Block schema.
- Block-level labels remain the main supervised target.
- Page and section labels can be derived from block labels with deterministic rules.
- Current image blocks do not yet have rendered crop paths; image modeling starts with deterministic stand-in features in lite mode.
- The first trainable target is a working research prototype, not a production classifier.

## 12. Approval Status

The following design decisions were approved in conversation:

- Use route 1 as the main direction: pure HMSAN-style deep model.
- Absorb route 3's boundary and section modeling ideas.
- Use `Document -> Page -> Block` as the normalized input hierarchy.
- Use joint labels for block classification, boundary detection, and section classification.
- Build a complete engineering skeleton with lite and full modes.
- Defer claims of real training effectiveness until more labeled PDFs are added.
