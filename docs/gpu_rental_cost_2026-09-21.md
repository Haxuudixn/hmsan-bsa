# 租用 GPU 完成训练的成本估算（2026-09-21）

> 基准：本机 `RTX 3060 12GB` 的**实测**训练速度（`outputs\hmsan_bsa_final\train.log`）。
> 租用价格：`RunPod` 官方 GraphQL API **实时抓取**（2026-09-21，见文末命令）。
> 国内厂商（AutoDL 等）价格为网页 JS 渲染 + 接口鉴权，**本次未能核实**，文中单独标注。

## 1 先把"要多少算力"算清楚（全部基于实测）

### 1.1 单次训练成本（实测，非估算）

| 项目 | 实测值 | 来源 |
|---|---|---|
| 8 epoch 完整训练（303 train + 65 val 段/epoch） | **20 h 18 min** | `train.log` 成功那次 |
| 单 epoch | **2.54 h** | 20.30 ÷ 8 |
| 协议 P3（固定 3 epoch）单配置 | **7.62 h** | 2.54 × 3 |
| 单段 train forward+backward | 30.2 s | 9144 s ÷ 303 |
| 单段 test forward-only（bf16） | 4.98~6.37 s → 66 段 ≈ 11.6 min | `eval.log` |
| 单次 val（65 段） | ≈ 13 min | — |

### 1.2 三个方案要跑多少"3060 小时"

| 方案 | 配置构成 | 3060 小时 |
|---|---|---|
| **S 档**（最小可发表） | P1.1（冻结 1.5 h + 解冻 7.6 h）+ A6（7.6 h）+ B1（1.5 h）+ eval | **≈ 19 h** |
| **路径 2**（推荐：消融在冻结协议下跑） | 12 个冻结配置 × 1.5 h + 基线 3 h + ★5×2 seed 15 h + eval 4 h | **≈ 40 h** |
| **路径 3**（纯解冻 M 档） | 11 消融 × 7.62 = 84 h + 基线 12 h + ★5×2 seed 76 h + eval 4 h | **≈ 176 h** |

> 路径 2 需要**复活 E0.2（RoBERTa 特征缓存）**，约 1~1.5 天开发。E0.1 只需 0.5 天。

### 1.3 关键前提：缓存能把冻结配置压到 1~1.5 h

冻结协议下文本编码器不更新，可离线缓存每块 768 维特征（456,602 块 ≈ 1.4 GB 常驻内存）。
这是路径 2 便宜的全部原因。**该数值是估算，尚未实测**（见第 5 节的"先花 1 块钱验证"）。

## 3 实测瓶颈：这份工作**不是**纯 GPU bound

2026-09-21 实测（`scripts\paper\` 一次性基准，取 64 张真实页面图片）：

| 操作 | 每张图片/每段文本 | 说明 |
|---|---|---|
| CPU 读 zip + PNG 解码（句柄常驻） | **14.3 ms/图** | 缓存命中 |
| CPU 读 zip + PNG 解码（每次重开句柄） | **128.5 ms/图** | 重开 zip 约 **114 ms/次** |
| GPU ViT 前向（bf16，batch 32） | **21.0 ms/图** | 3060 |
| GPU RoBERTa 前向（bf16，batch 32） | **0.4 ms/文本** | 3060 |

推论：

1. **CPU:GPU ≈ 0.68（图片分支）**，即图片分支里约 **40% 的时间花在 CPU 上**；
2. `train.py` 用 `num_workers=0`，CPU 加载与 GPU 计算**串行**。按每样本约 196 张图估算，
   CPU 侧约 2.8 s/样本，占实测 30.2 s/样本的 **≈ 9%**；
3. 因此加速比受 Amdahl 限制：

   | 条件 | 估算加速比 S（相对 3060） |
   |---|---|
   | 保持 `num_workers=0` | **≈ 3.5~5×** |
   | 改 `num_workers=4~8`（加载与计算重叠） | **≈ 5.5~7×** |

> **结论：租用前先设 `num_workers>0`，否则你是在为一块空转的 GPU 付钱。**

## 5 先花 1 块钱验证（强烈建议）

不要直接相信 1.3 与第 3 节的估算。先做一次 **$0.34 的标定**：

1. 租 1 台 RTX 4090 24G（Linux），挂载网络卷；
2. 只上传 **1~2 个 zip**（约 1~4 GB）先跑通；
3. 设 `num_workers=4`，用 `--ablation_preset full --epochs 1` 只跑 **20 个样本**并计时；
4. 读出 **s/样本**，与本地 30.2 s 相除，得到**真实的 S**；
5. 用真实 S 重算上表，再决定跑哪个方案。

这一步同时验证了三件事：环境能否跑通、`num_workers` 有没有收益、S 到底是多少。

## 6 与本地跑对比：租用到底值不值

| | 本地 3060 12GB | 租 RTX 4090 |
|---|---|---|
| 路径 2 墙钟 | **≈ 40 h（1.7 天）** | ≈ 10 h |
| 路径 3 墙钟 | **≈ 176 h（7.3 天）** | ≈ 44 h |
| 现金 | ¥0 | $3 ~ $15 |
| 风险 | 本机 8 GB 内存导致系统卡顿；长时间占机 | 上传摩擦 + 空转费 + 环境迁移 |

**结论**：**路径 2 本地就能跑完（约 1.7 天），租用主要是把 40 h 压到 10 h，省约 30 小时、花约 $3.4。**
若你要走路径 3（纯解冻），租用的价值才明显（省 5+ 天）。
换句话说——**这笔账的问题不是钱，而是"上传 37 GB"和"及时关机"。**

## 7 复现本文价格的命令

```powershell
$body='{"query":"query { gpuTypes { id displayName memoryInGb secureCloud communityCloud lowestPrice(input: {gpuCount: 1}) { minimumBidPrice uninterruptablePrice } } }"}'
$r=Invoke-WebRequest -Uri "https://api.runpod.io/graphql" -Method Post `
   -ContentType "application/json" -Headers @{"User-Agent"="Mozilla/5.0"} -Body $body -UseBasicParsing
($r.Content | ConvertFrom-Json).data.gpuTypes |
  ForEach-Object { [pscustomobject]@{ USDh=$_.lowestPrice.uninterruptablePrice; GPU=$_.displayName; VRAM=$_.memoryInGb } } |
  Where-Object USDh | Sort-Object USDh | Format-Table -AutoSize
```
